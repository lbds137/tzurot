### OWNER DIRECTION 2026-08-21 — the two-tier system is a bandaid; re-entry is not a resume

Owner, unprompted, after a second stale-memory incident (TASK-671): _"our current two tier memory system is a bandaid in the scheme of things. I want something far more intelligent in the future"_ — and, separately and firmly, **"I don't want to delete anything."**

Two things this changes, both concrete rather than atmospheric:

**1. Re-entry framing.** The state the owner calls "two-tier" is not the accepted architecture — it is Phase 2 of it, shipped in isolation. The governing artifact already specifies typed memories beyond episode/fact (reflection, canon), a relationship layer, consolidation and curation; phases 3-6 were never built because they are evidence-gated, and the gates never opened. So the question at re-entry is NOT "resume phases 3-6". It is: **does the accepted artifact still describe the system the owner wants, or is the artifact itself now up for revision?** That is an owner call and it must be asked BEFORE any re-entry design pass, because LID's HLD step (the recorded re-entry format) starts by assuming a target architecture. Asking it after the HLD is written wastes the pass.

**2. The backfill posture is the line item the owner's statement actually contradicts.** This file records _"Backfill posture: no bulk re-extraction of the existing corpus; old episodes get retrieval gains as-is."_ A materially more intelligent derived layer over an existing corpus is a bulk re-derivation almost by definition, so that row is now in tension with the stated direction and should be re-decided at re-entry rather than inherited.

The reconciliation is available and worth stating plainly, because it makes "lobotomy" and "delete nothing" compatible rather than opposed: **episodes are the source record; everything above them is derived and rebuildable.** `MemoryFact.sourceMemoryIds` already records the provenance link. So an arbitrarily radical redesign of the derived layer costs zero episode deletions - it is a re-derivation, not a purge. What the owner called a lobotomy is a rebuild of the derived layer, and the archive is the substrate that makes it safe. The "no deletion" instinct and the "far more intelligent" instinct do not trade off against each other; only the compute bill does.

Corollary for whoever runs the re-entry: the no-bulk-re-extraction posture was a COST decision, not a correctness one. Re-decide it on cost with a current number, not by inheriting the row.
